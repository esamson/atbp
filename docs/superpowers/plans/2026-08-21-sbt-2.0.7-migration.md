# sbt 2.0.7 Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate the atbp build from sbt 1.12.15 to sbt 2.0.7, replacing `liga-common` `crossProject` with built-in `projectMatrix`, and leave compile/test/`fixup`/CI green.

**Architecture:** Pin sbt 2.0.7, drop portable-scala crossproject, declare `liga-common` as a JVM+JS `projectMatrix` over shared `liga-common/src`, migrate `ThisBuild` settings to sbt 2 bare/common settings (single org `ph.samson.atbp`), opt side-effecting tasks out of disk cache with `Def.uncached`, then regenerate sbt-github-actions workflows for the unified `target/` layout.

**Tech Stack:** sbt 2.0.7, Scala 3.8.4 (app + metabuild), Scala.js 1.22.0, ZIO test, sbt-github-actions, sbt-native-packager, scalafmt/scalafix.

## Global Constraints

- sbt version must be exactly `2.0.7` in `project/build.properties`
- Application `scalaVersion` remains `3.8.4`
- Published `organization` is exactly `ph.samson.atbp` (remove stale `samson.ph`)
- Remove `sbt-scalajs-crossproject`; do not re-add it
- Keep `liga-common` sources under `liga-common/src/...` (no source move)
- After any `*.sbt` / `project/` edit in this work, use `sbt --batch` (not `--client`) until the build definition stabilizes
- Never run interactive sbt (`console`, bare `sbt`, `~compile`)
- For commits that touch Scala or build files: run the AGENTS.md `fixup` loop (`git add` → `sbt --batch fixup` → `git status` until clean) before committing
- Do not rewrite non-liga modules into matrices; do not change library dependency versions unless required for sbt 2 load

### Task 4: Make the build compile under sbt 2 (caching + metabuild fixes)

**Files:**
- Modify: `build.sbt` (`liga` resourceGenerators; any other failing custom tasks)
- Modify: other `*.sbt` / `project/*.scala` only as required by compiler/load errors

**Interfaces:**
- Consumes: `ligaJs` / `ligaCommonJvm` / `ligaCommonJsRow` from Task 3
- Produces: `Compile / resourceGenerators` wrapped in `Def.uncached` so JS copy always runs; successful `compile`

- [ ] **Step 1: Wrap the liga JS resource generator in `Def.uncached`**

Replace the `Compile / resourceGenerators += Def.task { ... }.taskValue` block on `liga` with:

```scala
Compile / resourceGenerators += Def.uncached {
  Def.task {
    val _ = (ligaJs / Compile / fastLinkJS).value
    val linkerOut =
      (ligaJs / Compile / fastLinkJS / scalaJSLinkerOutputDirectory).value
    val jsDest = (Compile / resourceManaged).value / "liga" / "web" / "js"
    IO.createDirectory(jsDest)
    val jsFiles = (linkerOut ** "*.js").get
    jsFiles.foreach { src =>
      val dest = jsDest / src.getName
      if (!dest.exists || dest.lastModified < src.lastModified) {
        IO.copyFile(src, dest)
      }
    }
    jsFiles.map(src => jsDest / src.getName)
  }.taskValue
}
```

If that form does not typecheck, use the sbt 2 documented shape that your error message points to — typically:

```scala
Compile / resourceGenerators += Def.taskDyn {
  Def.uncached {
    Def.task { /* same body returning Seq[File] */ }
  }
}.taskValue
```

or assign:

```scala
Compile / resourceGenerators += Def.uncached(Def.task { /* body */ }).taskValue
```

Choose the variant that compiles; keep the copy semantics identical.

Expected: `[success]`. If errors mention `fileInputExcludeFilter`, `DirectoryFilter`, missing givens, or postfix ops, fix with the smallest change in the reported file and re-run until success.
