**Goal:** Resume PR #291 on current `main`: rebase `sbt-2`, pin sbt 2.0.9, take latest sbt plugins, drop workarounds those releases made unnecessary, and leave load/compile/test/`fixup`/generated CI green.

### Rebase conflict policy (all tasks)

Stay on branch `sbt-2`. Use `git rebase origin/main` (never `git rebase -i`).

When rebasing `sbt-2` onto `origin/main`, git’s labels are inverted:

- `--ours` / “ours” = `origin/main` (the new base)
- `--theirs` / “theirs” = the `sbt-2` commit being replayed

**sbt 2 structure wins** (even when it comes from “theirs”):

- `projectMatrix` for `liga-common`; `ligaCommonJvm` / `ligaCommonJsRow`
- no `sbt-scalajs-crossproject` and no `PlatformDepsPlugin` / `%%%`
- bare common settings for org/scalaVersion/semanticdb (already on `sbt-2`)
- sbt 2 unified `target/out/…` layout
- `Def.uncached` on liga’s JS resource copy
- `DirectoryFilter.toNio` in `md2c` (already on both sides; leave as-is)

**`main` wins on** (even when it comes from “ours”):

- Scala version (`3.9.0` as of this spec → `lazy val scala3V = "3.9.0"`)
- application/feature code (md2c Mermaid/D2, liga spatial brackets, HTTP retry, Docker multi-arch + d2 install, `Compile/Test / run / fork := true`)
- plugin *versions* in `project/plugins.sbt`
- library versions in `project/Dependencies.scala`

**Pin:** `project/build.properties` must not become 1.13.0. If that file conflicts, write `sbt.version=2.0.9` immediately. If the old pin commit applies cleanly as 2.0.7, leave it for Task 2.

Likely overlapping files: `build.sbt`, `docs/liga/map.md`, `github.sbt`, `.github/workflows/ci.yml`, `project/build.properties`, `project/Dependencies.scala`, `project/plugins.sbt`.
