# sbt 2.0.7 migration design

Date: 2026-08-21  
Status: approved (approach B)

## Goal

Migrate this build from **sbt 1.12.15** to **sbt 2.0.7**, including rewriting `liga-common` from portable-scala `crossProject` to sbt 2’s built-in **project matrix**. After migration, the build loads, compiles, tests, and `fixup` succeed; GitHub Actions workflows are regenerated for sbt 2 layout.

## Non-goals

- Rewriting other modules into project matrices
- Changing the application Scala version (remains **3.8.4**)
- Upgrading the system sbt runner beyond what the project pin requires
- Opportunistic refactors unrelated to the migration

## Context

- Multi-module Scala 3.8.4 build with JVM apps and a Scala.js UI (`liga` / `liga-js`)
- Shared Pure sources live in `liga-common/src` via `crossProject` + `sbt-scalajs-crossproject`
- Plugins in use: scalafix, scalafmt, ci-release, dynver, github-actions, native-packager, scalajs, tpolecat, and currently portable-scala crossproject
- CI is generated by sbt-github-actions; artifact paths still assume per-module `*/target` and `liga-common/.jvm|/.js/target`
- Agent tooling expects `sbt --client` normally and `sbt --batch` after build-definition edits

## Approach

**Approach B — full semantic migration + project matrix for `liga-common`.**

Rejected alternatives:

- **A** — keep `crossProject` (bump plugin to 1.4.0 only): smaller diff, less idiomatic on sbt 2
- **C** — version pin only: leaves `ThisBuild`, CI paths, and caching half-migrated

## Design

### 1. Version pin

Set in `project/build.properties`:

```properties
sbt.version=2.0.7
```

### 2. Plugins

| Action | Plugin | Notes |
| --- | --- | --- |
| Keep | `sbt-scalajs` 1.22.0 | Already published for sbt 2 |
| Keep | scalafix, scalafmt, ci-release, dynver, github-actions, native-packager, tpolecat | Current versions already have `_sbt2_3` artifacts; bump only if load fails |
| Remove | `sbt-scalajs-crossproject` | Replaced by built-in `projectMatrix` |

### 3. `liga-common` → `projectMatrix`

Replace:

```scala
lazy val ligaCommon = crossProject(JSPlatform, JVMPlatform)
  .crossType(CrossType.Pure)
  .in(file("liga-common"))
  // ...
```

with an sbt 2 project matrix that declares JVM and JS platforms for Scala **3.8.4**, keeping shared sources under `liga-common/src/...`.

Wire consumers with matrix accessors (exact API as in sbt 2 docs), for example:

- `liga` depends on the JVM row
- `ligaJs` depends on the JS row
- `root` aggregates both rows (or the matrix’s aggregate set)

Remove `sbtcrossproject` imports from `build.sbt`.

Remove obsolete crossproject layout leftovers under `liga-common/.jvm` and `liga-common/.js` if they remain after the switch (targets/caches only; sources stay in `liga-common/src`).

Update docs that mention `liga-common.jvm` / crossproject layout only if they would be wrong after the rename of project IDs (prefer factual project-id updates in `docs/liga/map.md` if IDs change).

### 4. Dependencies

In `project/Dependencies.scala`:

- Drop `PlatformDepsPlugin` / `%%%` usage for this build
- Use platform-aware `%%` (and `Def.setting` where a setting context is still required)
- Keep the same library coordinates and versions

### 5. Bare / common settings (replace `ThisBuild`)

sbt 2 treats bare settings as common settings injected into all subprojects. Migrate existing `ThisBuild / …` keys in `build.sbt`, `publish.sbt`, `github.sbt`, and `fixup.sbt` to bare settings (or explicitly scoped settings where root-only behavior is required).

**Organization:** today `build.sbt` sets `ThisBuild / organization := "samson.ph"` and `publish.sbt` sets `ThisBuild / organization := "ph.samson.atbp"`. Keep a single published organization: **`ph.samson.atbp`**. Remove the stale `samson.ph` assignment.

### 6. Task caching / custom tasks

sbt 2 caches tasks by default. Side-effecting or non-`JsonFormat` results must opt out.

Likely touchpoint: `liga`’s `Compile / resourceGenerators` that copies `ligaJs` `fastLinkJS` output into managed resources — wrap with `Def.uncached { … }` if the build rejects caching or would skip the copy on cache hit.

Apply the same pattern to any other custom task that fails load or silently skips side effects.

### 7. Other build-file fixes

Fix Scala 3 metabuild issues as they appear (imports, postfix calls, File/NIO APIs such as `DirectoryFilter.toNio` / `fileInputExcludeFilter` in `md2c`). Prefer the smallest change that loads and preserves behavior.

### 8. CI / workflows

After the build loads under sbt 2:

1. Run github-actions generation (`githubWorkflowGenerate` or the project’s equivalent)
2. Commit regenerated `.github/workflows/*`
3. Ensure target archive / download paths match sbt 2’s unified `target/` layout (no reliance on `liga-common/.jvm/target` style paths)

### 9. Verification

During this task, use `sbt --batch` because build definition files change.

Gate:

1. Build loads on 2.0.7
2. `compile` succeeds (including JS link path for liga)
3. Tests relevant to changed modules pass (`liga` / `liga-common` / `liga-js` at minimum; prefer full `test` if runtime is acceptable)
4. `fixup` succeeds and, for any commit that includes Scala/build changes, the AGENTS.md fixup loop leaves a clean intended tree

## Risks

| Risk | Mitigation |
| --- | --- |
| Matrix project ID / path differs from `ligaCommon.jvm` / `.js` | Update aggregate/`dependsOn` and any docs that name IDs; regenerate CI paths |
| A plugin lacks a working sbt 2 artifact despite Maven metadata | Bump or temporarily drop only if required to load; prefer keep |
| Cached resource generator skips JS copy | `Def.uncached` |
| GHA still packs old target dirs | Regenerate workflows; verify archive step |

## Success criteria

- `project/build.properties` pins **2.0.7**
- No `sbt-scalajs-crossproject` dependency
- `liga-common` is a `projectMatrix` with JVM + JS rows sharing `liga-common/src`
- Organization is consistently **`ph.samson.atbp`**
- Workflows regenerated for sbt 2
- Load, compile, tests, and `fixup` succeed as above
