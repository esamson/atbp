# sbt 2.0.9 upgrade design

Date: 2026-09-20  
Status: approved (rebase, then empirical workaround cleanup)  
PR: [#291](https://github.com/esamson/atbp/pull/291) (`sbt-2`)

This is a follow-on to [`2026-08-21-sbt-2.0.7-migration-design.md`](2026-08-21-sbt-2.0.7-migration-design.md). Leave that document as history; do not rewrite it as if the pin was always 2.0.9.

## Goal

Resume PR #291 on current `main`: rebase first, pin **sbt 2.0.9**, take the latest **sbt plugins** (for sbt 2 compatibility fixes), and drop compatibility workarounds that those fixes made unnecessary. After the work, the build loads, compiles, tests, and `fixup` succeed; GitHub Actions workflows are regenerated.

## Non-goals

- Rewriting more modules into project matrices
- Independently bumping application libraries in `project/Dependencies.scala` (versions that arrive via rebase from `main` stay)
- Independently bumping Scala; after rebase it is whatever `main` has (**3.9.0** as of this spec)
- Removing the native-packager `lintUnused` suppressions until a plugin release actually fixes [sbt-native-packager#1761](https://github.com/sbt/sbt-native-packager/issues/1761)
- Dropping `Def.uncached` on liga’s JS resource copy
- Opportunistic refactors unrelated to this upgrade

## Context

- Branch `sbt-2` already migrated to sbt **2.0.7**: `liga-common` is a `projectMatrix`, `sbt-scalajs-crossproject` is gone, most `ThisBuild` keys are bare common settings, CI uses unified `target/out/…`.
- `sbt-2` is behind `origin/main` (19 commits at spec time): Scala 3.9.0, sbt-github-actions 0.32.0, sbt-ci-release 1.12.1, md2c Mermaid/D2 work, liga spatial brackets, multi-arch Docker, and sbt 1.13.0 on `main` (must not win over the sbt 2 pin).
- sbt **2.0.8** fixed ThisBuild-scoped bare settings ([sbt#9674](https://github.com/sbt/sbt/pull/9674)). That is why `github.sbt` had to restore `ThisBuild /` after the first migration (generated CI leaked JDK 8).
- sbt **2.0.9** is the current 2.x patch (cache hermeticity, Windows JAR creation, pipelined Java/macros, runner script).
- After rebase, expected plugin pins (take a newer plugin if one appears at implementation time):

  | Plugin | After rebase / target |
  | --- | --- |
  | sbt | **2.0.9** |
  | sbt-github-actions | 0.32.0 |
  | sbt-ci-release | 1.12.1 |
  | sbt-scalafix | 0.14.7 |
  | sbt-dynver | 5.1.1 |
  | sbt-native-packager | 1.11.7 |
  | sbt-scalafmt | 2.6.2 |
  | sbt-scalajs | 1.22.0 |
  | sbt-tpolecat | 0.5.7 |

## Approach

**Rebase onto `main`, then bump sbt and empirically drop workarounds.**

Rejected alternatives:

- Rebase and bump versions only (leave every workaround in place unless a changelog names it): leaves the `ThisBuild` restore that 2.0.8 was meant to make unnecessary.
- Merge `main` instead of rebase: avoids force-push, but this work was specified as rebase.

## Design

### 1. Rebase first

Stay on `sbt-2`. Do not start version bumps until the branch is rebased onto current `origin/main`.

Replay the existing sbt-2 commits onto `origin/main`. After a successful rebase, force-push `sbt-2` (the branch is already on the remote).

**Conflict policy**

- **sbt 2 structure wins:** project matrix for `liga-common`, no `sbt-scalajs-crossproject` (even if `main` bumped it to 1.4.0), bare common settings, sbt 2 target layout.
- **`main` wins on:** Scala version, application/feature code, and plugin *versions*.
- **Pin:** `project/build.properties` must be **2.0.9** before verification. If that file conflicts during rebase, resolve it to **2.0.9** immediately (not `main`’s 1.13.0 and not 2.0.7). If the old pin commit applies cleanly as 2.0.7, add a follow-up commit that bumps it to 2.0.9.
- If conflict resolution would change application behavior from `main`, stop and ask rather than guess.

### 2. Version pin and plugins

Set in `project/build.properties`:

```properties
sbt.version=2.0.9
```

Confirm `project/plugins.sbt` is at the latest plugin versions after rebase (table above). Do not add application-library bumps beyond what rebase brought from `main`.

During this task, use `sbt --batch` because build definition files change.

### 3. Workarounds (empirical, one at a time)

After 2.0.9 loads, try removing each item in isolation. Gate: the build loads without the old warning/error, then `compile` still works. If it fails, restore that item and leave a short comment pointing at the remaining cause.

| Item | Expected outcome | Why |
| --- | --- | --- |
| `ThisBuild /` on github-actions keys in `github.sbt` | **Drop** — restore bare settings | sbt 2.0.8 fixed ThisBuild-scoped bare settings |
| `Test / exportJars := false` | **Verify** | Added during the matrix rewrite; keep only if load/compile still needs it |
| `Global / excludeLintKeys` in `package.sbt` | **Keep** | native-packager 1.11.7 still has issue 1761 |
| `Def.uncached` on liga’s JS resource copy | **Keep** | sbt 2 task cache semantics, not a plugin bug |

Not workarounds (leave as-is): `projectMatrix` for `liga-common`, `DirectoryFilter.toNio` in `md2c`, dropping `sbt-scalajs-crossproject`.

After dropping `ThisBuild` on github-actions keys, regenerate workflows and confirm Java stays **Temurin 25** (the original failure mode was plugin-default JDK 8).

### 4. CI / workflows

After the build loads under 2.0.9:

1. Run `githubWorkflowGenerate` (or the project’s equivalent) and commit regenerated `.github/workflows/*`.
2. `githubWorkflowCheck` must pass.
3. Target archive paths remain sbt 2 `target/out/…` (including matrix JVM/JS rows).
4. Generated actions should match sbt-github-actions 0.32.0 (including `actions/setup-java@v6`).

### 5. PR metadata

Update PR #291 title and body from “2.0.7” to this upgrade (2.0.9, rebase onto `main`, workaround cleanup). Do not open a second PR.

## Verification

1. Rebase onto `origin/main` completed; `sbt-2` force-pushed.
2. Build loads on **2.0.9** with no unexpected `lintUnused` noise beyond what we intentionally kept.
3. `compile` succeeds, including the liga JS resource copy.
4. `test` succeeds on the rebased tree (includes tests `main` added).
5. Workflows regenerated as in §4; Java is Temurin 25.
6. For any commit that touches Scala or build files: AGENTS.md `fixup` loop (`git add` → `sbt --batch fixup` → `git status`) until that commit’s intended tree is clean.

## Risks

| Risk | Mitigation |
| --- | --- |
| Rebase conflicts in `build.sbt` / plugins / workflows | Conflict policy in §1; stop if app behavior from `main` is unclear |
| Bare github-actions settings still miss ThisBuild keys on 2.0.9 | Restore `ThisBuild /` and note that 9674 was insufficient for this plugin |
| Force-push overwrites remote `sbt-2` | Expected for this rebase; do not force-push other branches |
| native-packager still warns after 2.0.9 | Keep `excludeLintKeys`; do not treat as a failed upgrade |

## Success criteria

- Branch is rebased onto current `main` and force-pushed
- `project/build.properties` pins **2.0.9**
- Plugins are at latest as of implementation (no extra application-library bumps)
- Workarounds match the table in §3 (dropped, kept, or restored with a comment after a failed trial)
- Workflows regenerated; Temurin 25 preserved
- Load, compile, tests, and `fixup` succeed as above
- PR #291 describes this upgrade, not only 2.0.7
